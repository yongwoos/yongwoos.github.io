## AS
**AS(Autonomous System, 자치 시스템)** 은 **하나의 관리 주체가 운영하는 IP 네트워크들의 집합**이다.

쉽게 말하면,

> **하나의 조직이 하나의 라우팅 정책으로 관리하는 네트워크**를 AS라고 한다.

예를 들어

```text
             인터넷

        ┌───────────────┐
        │    KT AS      │
        └───────────────┘
                │
        ┌───────────────┐
        │ SK브로드밴드 AS │
        └───────────────┘
                │
        ┌───────────────┐
        │   Google AS   │
        └───────────────┘
```

각 ISP나 대기업은 자기만의 AS를 운영한다.

### AS 안에는 무엇이 있나?

AS 내부에는 수많은 라우터와 네트워크가 있다.

```text
          AS 65001

      R1 ─── R2 ─── R3
       │      │
      LAN1   LAN2
```

이 안에서는 OSPF나 RIP 같은 **IGP**를 사용해 경로를 계산한다.

### AS 번호(ASN)

각 AS에는 **ASN(Autonomous System Number)** 이 부여된다.

예를 들어

* AS 3356
* AS 15169 (Google)
* AS 32934 (Meta)
* AS 16509 (Amazon)

처럼 전 세계에서 고유한 번호를 가진다.

### AS끼리는 어떻게 통신하나?

AS와 AS 사이에서는 **BGP**를 사용한다.

```text
        AS 100              AS 200

   R1 ─ R2 ========= R3 ─ R4
          BGP
```

* AS 100 내부 → OSPF
* AS 200 내부 → OSPF
* AS 100 ↔ AS 200 → BGP

### 왜 AS를 나누는가?

인터넷 전체를 하나의 네트워크처럼 관리하는 것은 현실적으로 불가능하다.

대신

* KT는 KT가 관리
* SK브로드밴드는 SK브로드밴드가 관리
* Google은 Google이 관리

하고, 서로 필요한 경로 정보만 BGP로 교환한다.

### IGP와 EGP의 관계

```text
         인터넷

      AS 100        AS 200

    OSPF/RIP       OSPF/RIP
        │              │
        └──── BGP ─────┘
```

* **AS 내부**: IGP(OSPF, RIP 등)
* **AS 간**: BGP

### 한 줄로 정리

**AS는 하나의 조직이 동일한 라우팅 정책으로 운영하는 네트워크의 집합**이며, **AS 내부에서는 IGP를 사용하고, AS와 AS 사이에서는 BGP를 사용한다.**

## OSPF
OSPF(Open Shortest Path First)는 **링크 상태(Link State) 라우팅 프로토콜**이다. 같은 자치 시스템(AS) 내부에서 사용하는 **IGP(Interior Gateway Protocol)** 이며, RIP보다 훨씬 빠르고 대규모 네트워크에 적합하다.

### 핵심 개념

#### 1. 링크 상태(Link State)

각 라우터는 자신과 직접 연결된 링크의 상태(대역폭, 연결 여부 등)를 파악한다.

예를 들어

```
A ── B ── C
 \       /
   \── D
```

라우터 B는

* A와 연결
* C와 연결

이라는 정보를 가진다.

이 정보를 다른 모든 OSPF 라우터에게 전파한다.

### 2. LSA(Link State Advertisement)

각 라우터는 자신의 링크 정보를 **LSA**라는 형태로 광고한다.

예를 들면

```
Router B
- A와 연결 (Cost=10)
- C와 연결 (Cost=5)
```

이 정보를 모든 라우터에게 보낸다.

### 3. Flooding

LSA는 **플러딩(Flooding)** 방식으로 네트워크 전체에 퍼진다.

즉

```
A → B
B → C
B → D
C → ...
D → ...
```

중계하면서 모두가 같은 정보를 갖게 된다.

결과적으로 모든 라우터는 동일한 네트워크 지도를 가지게 된다.

### 4. LSDB(Link State Database)

모든 LSA를 모아 만든 것이 LSDB이다.

예를 들어

```
A-B Cost 10
B-C Cost 5
A-D Cost 3
D-C Cost 2
```

이런 전체 토폴로지를 모든 라우터가 동일하게 보관한다.

### 5. SPF 알고리즘

LSDB를 기반으로 **Dijkstra's algorithm(SPF 알고리즘)** 을 수행하여 최단 경로를 계산한다.

예를 들어

```
A → B → C = 15
A → D → C = 5
```

이면

```
A → D → C
```

를 선택한다.

### Cost

OSPF는 홉 수가 아니라 **Cost**를 사용한다.

Cost는 일반적으로

```
Cost = 기준 대역폭 / 링크 대역폭
```

으로 계산된다.

예)

| 링크 속도    |                 Cost |
| -------- | -------------------: |
| 10 Mbps  |                   10 |
| 100 Mbps |                    1 |
| 1 Gbps   | 1(최소값으로 설정되는 경우가 많음) |

즉 대역폭이 높은 링크를 선호한다.

### RIP와 비교

| RIP             | OSPF              |
| --------------- | ----------------- |
| 거리 벡터           | 링크 상태             |
| Hop Count 사용    | Cost 사용           |
| 최대 15 Hop       | 제한 없음(실질적으로 매우 큼) |
| 주기적으로 전체 테이블 전송 | 변화가 있을 때만 LSA 전송  |
| 수렴이 느림          | 수렴이 매우 빠름         |
| 소규모 네트워크        | 중·대규모 네트워크        |

### 동작 과정

```
① 인접 라우터 발견(Hello 패킷)

↓

② 인접 관계(Adjacency) 형성

↓

③ LSA 교환

↓

④ 모든 라우터가 LSDB 생성

↓

⑤ Dijkstra 알고리즘 실행

↓

⑥ 라우팅 테이블 생성

↓

⑦ 데이터 전송
```

### 한 줄로 정리

OSPF는 **모든 라우터가 네트워크 전체 지도를 공유(LSDB)한 뒤, 각자 Dijkstra 알고리즘으로 최단 경로를 계산하는 링크 상태 기반 라우팅 프로토콜**이다. RIP처럼 단순히 홉 수를 비교하는 것이 아니라 링크의 Cost를 기준으로 더 효율적인 경로를 선택한다.

## RIP
RIP(Routing Information Protocol)은 **거리 벡터(Distance Vector) 라우팅 프로토콜**이며, 같은 자치 시스템(AS) 내부에서 사용하는 **IGP(Interior Gateway Protocol)** 이다. 가장 오래된 라우팅 프로토콜 중 하나로, 구조는 단순하지만 대규모 네트워크에는 적합하지 않다.

### 핵심 개념

RIP에서 각 라우터는 **전체 네트워크 구조를 모른다.**

대신 **"목적지까지 몇 홉(Hop)인가?"** 만 알고 있다.

예를 들어

```text
A ── B ── C ── D
```

라우터 B는

* A까지 1 Hop
* C까지 1 Hop
* D까지 2 Hop(C를 통해)

처럼 목적지까지의 거리만 저장한다.

### Distance Vector

Distance Vector는 말 그대로

* Distance = 거리(Hop 수)
* Vector = 어느 이웃을 통해 갈 것인지

를 의미한다.

예를 들어 B의 라우팅 테이블은

| 목적지 | 다음 라우터 | Hop |
| --- | ------ | --: |
| A   | A      |   1 |
| C   | C      |   1 |
| D   | C      |   2 |

처럼 저장된다.

### 동작 방식

각 라우터는 **주기적으로(기본 30초마다)** 자신의 라우팅 테이블을 이웃 라우터에게 보낸다.

예를 들어

```text
A ── B ── C
```

B는 C에게

```text
A : 1 Hop
B : 0 Hop
```

이라는 정보를 보낸다.

그러면 C는

> "B를 거치면 A까지 2 Hop이구나."

라고 계산하여 자신의 테이블을 갱신한다.

### Bellman-Ford 알고리즘

RIP는 **Bellman–Ford algorithm** 을 사용한다.

새로운 경로 정보가 오면

```text
새 거리 = 이웃까지 거리(1) + 이웃이 알려준 거리
```

를 계산한다.

예를 들어

```text
B가 A까지 3 Hop이라고 알려줌

↓

나는 B까지 1 Hop

↓

A까지 총 4 Hop
```

### 메트릭(Metric)

RIP의 메트릭은 **Hop Count** 하나뿐이다.

```text
A → B → C → D

Hop = 3
```

대역폭이나 지연 시간은 고려하지 않는다.

### 최대 Hop

RIP는

* 최대 15 Hop까지 사용 가능
* 16 Hop은 도달 불가능(Infinite)

으로 간주한다.

그래서 네트워크가 커지면 사용할 수 없다.

### 문제점

예를 들어

```text
A ── B ── C
```

에서 A가 고장 났다고 하자.

B는 아직 모르고,

C는

> "A는 B를 통해 갈 수 있어."

라고 계속 알려줄 수 있다.

그러면

```text
A : 2 Hop
↓

3 Hop
↓

4 Hop
↓

...
↓

16 Hop
```

처럼 계속 증가하는 **Count to Infinity** 문제가 발생할 수 있다.

이를 줄이기 위해

* Split Horizon
* Poison Reverse
* Triggered Update
* Hold-down Timer

같은 기법을 사용한다.

### RIP와 OSPF 비교

| RIP             | OSPF          |
| --------------- | ------------- |
| 거리 벡터           | 링크 상태         |
| Bellman-Ford    | Dijkstra      |
| Hop Count       | Cost          |
| 최대 15 Hop       | 사실상 제한 없음     |
| 30초마다 전체 테이블 전송 | 변경된 링크 상태만 전송 |
| 수렴 느림           | 수렴 빠름         |
| 소규모 네트워크        | 중·대규모 네트워크    |

### 동작 과정

```text
① 이웃 라우터 발견

↓

② 라우팅 테이블 생성

↓

③ 30초마다 이웃에게 전체 라우팅 테이블 전송

↓

④ 받은 정보로 Bellman-Ford 계산

↓

⑤ 더 짧은 경로면 라우팅 테이블 갱신

↓

⑥ 데이터 전달
```

### OSPF와 가장 큰 차이

* **RIP**: "목적지까지 몇 홉인지"만 이웃에게 물어보며 최단 경로를 계산한다. 네트워크 전체 구조는 모른다.
* **OSPF**: 모든 라우터가 네트워크 전체 토폴로지(LSDB)를 공유한 뒤, 각자 Dijkstra 알고리즘으로 최단 경로를 계산한다.

## IGP
**IGP(Interior Gateway Protocol)** 는 **하나의 AS(Autonomous System, 자치 시스템) 내부에서 사용하는 라우팅 프로토콜**이다.

쉽게 말하면,

* **같은 조직(회사, ISP 내부, 학교 등) 안에서 라우터끼리 경로를 찾는 프로토콜**이다.

예를 들어

```text
             인터넷
                │
        ┌──────────────┐
        │   AS 65001   │
        │              │
        │ R1 ─ R2 ─ R3 │
        │   \      /   │
        │     R4       │
        └──────────────┘
```

AS 65001 내부의 R1, R2, R3, R4가 서로 경로 정보를 교환할 때 사용하는 것이 IGP이다.

대표적인 IGP는 다음과 같다.

* RIP
* OSPF
* IS-IS
* EIGRP(사실상 Cisco 전용)

### 왜 필요한가?

예를 들어 R1이 R3으로 패킷을 보내려면

```text
R1 → R2 → R3
```

으로 갈지,

```text
R1 → R4 → R3
```

으로 갈지 알아야 한다.

이 경로를 자동으로 계산해 주는 것이 IGP이다.

### IGP와 EGP의 차이

| IGP              | EGP            |
| ---------------- | -------------- |
| AS 내부에서 사용       | AS와 AS 사이에서 사용 |
| 같은 조직 내부         | 서로 다른 조직 간     |
| RIP, OSPF, IS-IS | BGP            |

예를 들어

```text
        AS 65001             AS 65002
   R1 ─ R2 ─ Border ─ Border ─ R5
```

* AS 65001 내부에서는 **OSPF**를 사용할 수 있다.
* AS 65002 내부에서도 **OSPF**를 사용할 수 있다.
* 두 AS의 경계(Border Router)끼리는 **BGP**를 사용해 경로를 교환한다.

### 한 줄로 정리

**IGP는 하나의 AS 내부에서 라우터들이 최적의 경로를 계산하기 위해 사용하는 라우팅 프로토콜**이며, 대표적으로 RIP와 OSPF가 있다. AS와 AS 사이의 경로 교환에는 BGP와 같은 EGP가 사용된다.

## EGP-BGP
**EGP(Exterior Gateway Protocol)** 는 **서로 다른 AS(Autonomous System) 간에 라우팅 정보를 교환하는 프로토콜의 분류**이고, 현재 인터넷에서는 사실상 **BGP** 가 유일하게 사용된다.

즉,

* **IGP**: AS 내부
* **BGP(EGP)**: AS와 AS 사이

에서 사용된다.

예를 들어,

```text
         AS 100                 AS 200
   R1 ─── R2 ======== R3 ─── R4
          ↑          ↑
      Border Router  Border Router
```

* AS 100 내부에서는 OSPF를 사용할 수 있다.
* AS 200 내부에서도 OSPF를 사용할 수 있다.
* R2와 R3는 BGP를 사용하여 경로를 교환한다.

### BGP는 무엇을 교환하나?

OSPF는

> "목적지까지 Cost가 얼마인가?"

를 계산한다.

RIP는

> "목적지까지 Hop이 몇 개인가?"

를 계산한다.

반면 BGP는

> **"어떤 AS들을 거쳐 가는가?"**

를 가장 중요하게 본다.

예를 들어 목적지 AS 400으로 가는 경로가

```text
경로 1
100 → 200 → 300 → 400

경로 2
100 → 500 → 400
```

라면,

BGP는 **AS-PATH**를 보고 정책에 따라 경로를 선택한다.

### Path Vector 방식

BGP는 **Path Vector** 라우팅 프로토콜이다.

즉, 목적지까지의 **AS 목록(AS-PATH)** 을 함께 광고한다.

예를 들어 AS 400이

```text
AS-PATH = 400
```

을 광고하면,

AS 300은

```text
300 → 400
```

으로 저장하고,

AS 200에는

```text
200 → 300 → 400
```

을 광고한다.

결국 AS 100은

```text
100 → 200 → 300 → 400
```

이라는 전체 AS 경로를 알게 된다.

### 왜 AS-PATH가 필요한가?

루프를 방지하기 위해서이다.

예를 들어 AS 100이 자신의 번호가 포함된

```text
100 → 200 → 300 → 100
```

이라는 경로를 받으면,

자신이 이미 경로에 포함되어 있으므로 해당 경로를 버린다.

### 특징

* AS 간 라우팅
* Path Vector 방식
* TCP(포트 179) 사용
* 정책 기반(Policy-based) 라우팅
* 인터넷 전체에서 사용

### IGP와 비교

| IGP(OSPF, RIP) | BGP                |
| -------------- | ------------------ |
| AS 내부          | AS 간               |
| 최단 경로 중심       | 정책 중심              |
| Cost, Hop 사용   | AS-PATH 등 여러 속성 사용 |
| 빠른 수렴          | 상대적으로 느린 수렴        |
| 내부 라우팅         | 인터넷 라우팅            |

### eBGP와 iBGP

BGP는 다시 두 가지로 나뉜다.

* **eBGP (External BGP)**: 서로 다른 AS 간에 사용하는 BGP
* **iBGP (Internal BGP)**: 같은 AS 내부에서 BGP 정보를 전달할 때 사용하는 BGP

예를 들어,

```text
AS 100                    AS 200

R1 ─── R2 ======= R3 ─── R4
       ↑ eBGP ↑

R1 ←──── iBGP ───→ R2
R3 ←──── iBGP ───→ R4
```

* R2와 R3는 **eBGP**
* R1과 R2, R3와 R4는 **iBGP**

를 사용한다.

### 한 줄로 정리

**BGP는 인터넷에서 서로 다른 AS들이 경로를 교환하는 Path Vector 기반의 EGP이며, 최단 거리보다 AS-PATH와 정책을 기준으로 경로를 선택하는 것이 가장 큰 특징이다.**
